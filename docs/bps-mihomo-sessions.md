# Excel / BPS 会话代理（本地试验）

基线：`e39898c680ecd69381e549ae54c97011107f1757`（v2.8.14）。

账号编辑及批量编辑的 Excel / BPS 区域新增「BPS 会话代理（故障自动换出口）」，默认关闭。沿用账号 ChatGPT OAuth，不需要额外登录或协议 sidecar。启用后 BPS 请求优先使用内置 Mihomo；关闭此代理选项恢复账号原代理，关闭 Excel / BPS 协议恢复原 Codex 路由。未命中 BPS 模型范围的请求不受影响。

## 会话行为

- 复用现有客户端线程 / `session_id` / `prompt_cache_key` 解析，按账号、API key 和执行会话隔离绑定；缺少可识别会话时，为该请求生成独立临时身份，同一请求的内部重试复用身份，结束后立即释放代理绑定。不会按相同提示词合并匿名请求；跨请求固定出口仍需客户端提供稳定会话标识。
- 新会话分配到当前绑定会话数最少的合格节点。同一账号的不同会话可以使用不同节点；健康会话的多轮及并发请求保持原节点。分配时先验证出口的 HTTPS 可达性，异常时自动选择其他合格节点。
- 每个请求持有独立引用直到响应体关闭。仍有请求执行的绑定不回收；显式会话空闲 30 分钟后回收，无标识请求在结束或获取失败时立即释放临时绑定。最多 4096 个绑定，容量满返回 503，不驱逐活跃会话。
- 节点故障、禁用、国家过滤排除、订阅删除或节点配置变化时，受影响会话在旧请求全部结束后自动改绑合格出口；进行中的请求不迁移。如果没有可用出口，返回 503，始终不回退直连，也不绕过国家过滤。
- 首次使用或健康缓存超过 30 秒时，通过该节点向固定的 BPS 根路径发 HEAD 请求，仅检查代理隧道、TLS 和 HTTP 可达性，不带 OAuth 或会话凭据、不调用模型、不跟随重定向。同一节点并发探测合并为一次，单次探测最长 5 秒，每次节点检查最多 3 次探测；一次会话获取最多尝试 3 个候选节点，总探测预算 15 秒。
- 连通性探测连续两次失败触发 60 秒冷却。冷却结束不直接恢复，必须连续两次探测成功；一次失败也会清除健康缓存，并使原会话在下次获取时优先换出口。状态仅用于 BPS，不修改打票节点状态或账号限流。
- 首次模型流中断立即隔离节点 5 分钟；30 分钟内再次断流按 10、20、30 分钟逐步延长，最多 30 分钟。短 HTTPS 探测成功不会清除最近的流故障记录；距上次断流超过 30 分钟后，下一次断流重新从 5 分钟开始。普通探测失败不能缩短已有长冷却。进行中的请求不迁移，不因客户端取消或正常上游 HTTP 拒绝施加流故障冷却。
- 当前请求最多额外尝试一次，必须同时满足：走托管会话代理、明确观测到 HTTP 建连开始、从未拿到可写连接、从未尝试发送请求头或读取请求体、没有响应、没有取消。额外尝试排除刚失败的出口。缺少追踪证据、可能已发送请求、收到 HTTP 错误或流中断时不重放；连接或流错误会使后续请求重新选择出口。
- 绑定保存在进程内存，Sub2API 重启会重新分配；不承诺跨服务重启维持原 IP。
- 代理节点固定不等于公网 IP 固定。动态 IP 供应商必须提供粘性出口；本实现不改写供应商用户名或伪造 session 参数，也不验证供应商的实际出口稳定性。

## Mihomo 接入

每个节点配置身份使用独立、不可改派的本地 mixed listener，端口从 `127.0.0.1:19000` 分配，最多 4096 个。端口按节点而非会话分配，200 个会话不需要 200 个监听端口。节点配置身份改变会分配新端口；旧端口设置为 REJECT，避免连接池误连其他节点。节点历史过多超过上限时配置更新失败，需要维护窗口重启清理进程内历史。

监听入口由内置 Mihomo 配置生成，复用已有订阅、动态代理及国家过滤；不会改动打票 selector，也不占用打票 gate。打票标记为 used 的节点仍可承载业务，failed/disabled 节点不能分配。HTTP/2 长连接策略保持现有实现，连接池由不同节点端口隔离。

首次升级需要内置 Mihomo 重新加载配置，生成这些监听入口。配置更新沿用现有候选配置验证和回滚流程。没有新增数据库迁移。

## 故障诊断

日志 `excel_bps.proxy_probe_failed` 记录请求上下文、脱敏节点摘要、本地监听地址和固定错误分类；`excel_bps.transport_failed` 记录账号 ID、会话哈希、监听端口、阶段、尝试次数和是否允许发送前重试。日志 `excel_bps.proxy_rebound` 记录换出口后的节点摘要和本地监听地址。Ops 上游尝试明细保存相同的固定分类，包括 DNS、TLS、连接拒绝/重置、超时和流不完整。

请求采集元数据保留脱敏错误分类和 HTTP trace 失败阶段，正文采集为零不能当作未发送证据。5xx 使用 server_error；HTTP 200 的流式失败仍记录 basispoints_stream_incomplete，并在采集列表和详情展示业务结局。旧记录缺少结局字段时保留“最终结果未确认”，不从 HTTP 200 推断成功。

不保存原始错误文本、供应商地址、代理认证、OAuth、会话原文或请求体；没有收到上游 HTTP 响应时不伪造上游状态码。探测通过只表示当时链路可达，不保证后续模型请求不会中断。

## 本地验证

```bash
cd backend
go test -tags=unit ./internal/mihomo ./internal/service ./internal/repository -run 'BPS|Excel|Collection|Country|Scheduler.*Extra' -count=1
go test -race ./internal/mihomo -count=1
MIHOMO_INSTALL_SMOKE=1 go test ./internal/mihomo -run '^TestCollectionWithOfficialKernel$' -count=1
cd ../frontend
pnpm test:run src/components/account/__tests__/EditAccountModal.spec.ts src/components/account/__tests__/BulkEditAccountModal.spec.ts
pnpm build
```

内核测试仅下载固定版本官方内核，使用本地模拟代理出口，验证两个会话分别出站、同会话复用出口以及配置重载后绑定不变。200 并发覆盖的是离线会话分配和引用计数，不代表真实 BPS 200 并发或账号风控已验证。
